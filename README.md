# gi_damage — расчёт урона отрядов Genshin Impact

Замена Excel-таблице: движок, в котором усиления, действующие только на часть
атак персонажа, описываются явно и не превращают расчёт в кашу из ссылок на ячейки.

Лист **«Мидзуки Сахароза»** перенесён целиком: все четыре отряда сходятся
с таблицей **до нуля** (0.000000 % расхождения).

```
python -m scripts.compare_with_excel      # сверка с таблицей
python -m scripts.run_mizuki_sucrose      # расчёт + примеры ростеров
python tests/test_mizuki_sucrose.py       # тесты (или python -m pytest tests -q)
```

Зависимостей нет — только стандартная библиотека Python 3.10+.

---

## 1. Главная идея: состояния вместо ветвлений

В таблице каждое временное усиление приходилось разворачивать в отдельные строки
(«Total EM on field», «Total EM on field instructor + Sucrose», …) и вручную
следить, какая строка куда подставляется. Здесь это делает движок.

**Состояние** — набор строковых тегов, описывающих обстановку в момент удара:

```python
from gi_damage.data.tags import ON, OFF, INST

frozenset({ON})            # персонаж на поле, временных окон нет
frozenset({OFF, INST})     # вне поля, работает окно «Инструктор + A4 Сахарозы»
```

* **Бафф** объявляет, при каких тегах он работает (`requires`) и при каких
  выключается (`excludes`). Постоянные и псевдопостоянные баффы `requires` не имеют —
  они действуют всегда.
* **Источник урона** объявляет, сколько раз он срабатывает в каждом состоянии.

Это и есть принцип из ТЗ: «взять все постоянные усиления, а потом по каждому
временному усилению добавить те источники урона, которые в нём происходят».

```python
stellar_swirl(
    "Навык — звёздное рассеивание (МС)", "em", mv=10.0, element="anemo",
    occurrences=[
        occ(1, ON),          # 1 раз вне окна Инструктора
        occ(3, ON, INST),    # 3 раза внутри окна
    ],
)
```

Движок сам посчитает статы Мидзуки отдельно для `{on_field}` и для
`{on_field, instructor}` и применит их к нужным ударам.

## 3. Быстрый старт

```python
from gi_damage.presets.mizuki_sucrose_odette_cmc import all_teams
from gi_damage.core.report import team_summary, source_breakdown

for name, team in all_teams(excel_compat=False).items():
    result = team.compute()
    print(team_summary(result))       # урон по персонажам, DPR, DPS
    print(source_breakdown(result))   # разбивка по источникам
```

### Массовые расчёты (ростеры)

```python
from gi_damage.core.roster import Roster, Variation
from gi_damage.data.weapons import WANDERER_SONG, SUNNY_MORNING_SLEEP_IN
from gi_damage.core.report import compare

roster = Roster(team, [
    Variation(slot="Мидзуки", weapons=[WANDERER_SONG.at(5),
                                       SUNNY_MORNING_SLEEP_IN.at(1)]),
    Variation(slot="Одетта",  constellations=[0, 1, 2]),
])
print(compare(roster.ranked("dps")))   # декартово произведение всех осей
```

`Variation` умеет менять: `weapons`, `constellations`, `artifact_sets` и
`builds` (полная замена персонажа в слоте — триггеры реакций переставляются
автоматически).

Если замена меняет что-то на уровне отряда (например C2 Мидзуки снижает
сопротивление цели), используйте `Roster(..., tweak=функция)` — пример есть
в `scripts/run_mizuki_sucrose.py`.

## 4. Как добавить своё

### Персонаж

```python
from gi_damage.core.entities import Character, Constellation
from gi_damage.core.sources import elemental, stellar_swirl, occ
from gi_damage.core.buffs import Buff, temp, SELF, TEAM, OTHERS
from gi_damage.core.stats import S
from gi_damage.data.tags import ON, OFF, INST

MY_CHAR = Character(
    name="Имя",
    element="cryo",
    default_field=OFF,           # где персонаж во время реакций
    crit_mode="expected",        # expected | always | none | balance
    stats={S.BASE_ATK: 300.0},
    buffs=(
        Buff(S.ATK_PCT, 0.20, target=SELF),                    # постоянный
        temp(S.DMG_BONUS, 0.30, INST, target=TEAM),            # временный
        Buff(S.FLAT_EM, lambda ctx: 0.25 * ctx.own("em"),      # зависит от статов
             target=OTHERS),
    ),
    sources=(
        elemental("Навык", "atk", 1.0394 + 0.8084 * 20, "cryo", "skill",
                  [occ(1, ON), occ(3, ON, INST)]),
    ),
    constellations={1: Constellation(1, "C1", stats={S.CRIT_DMG: 0.2})},
)
```

Множители таланта пишутся **в долях**: `103.94 %` → `1.0394`. Формулы можно
переносить из таблицы как есть: `mv=1.0394 + 0.8084 * 20`.

### Баффы, зависящие от других персонажей

Значение баффа может быть функцией от контекста:

```python
# A4 Сахарозы: +20 % её МС всем остальным
temp(S.FLAT_EM,
     lambda ctx: 0.20 * ctx.stat("Сахароза", "em", frozenset({ON})),
     INST, target=OTHERS)

# Талант Мидзуки: бонус урона SSW = 4.5 % за каждые 100 её МС,
# считается в том же окне Инструктора, в котором находится получатель
Buff(S.SSW_BONUS,
     lambda ctx: 0.045 * ctx.stat("Мидзуки", "em", ctx.mirror(ON, keep=[INST])) / 100,
     target=OTHERS, requires=(OFF,))
```

Взаимные зависимости («МС Сахарозы → МС Мидзуки → бонус отряду») разрешаются
итеративно, зацикливания не будет (`Config.resolve_passes`, по умолчанию 4).

Доступно в контексте: `ctx.stat(персонаж, стат, состояние)`, `ctx.own(стат)`,
`ctx.base(персонаж, стат)` (значение до любых баффов отряда),
`ctx.mirror(теги, keep=[...])`, `ctx.has(тег)`.

### Сопротивление цели

Сопротивление — такой же стат, как любой другой, поэтому снижение резистов
может быть временным и разным для разных источников урона.

```python
Enemy(res={"anemo": 0.10, "cryo": 0.10}, def_mult=0.4875)   # БАЗОВОЕ сопр. цели
```

Всё, что его снижает, пишется баффом `res_reduction` (или
`res_reduction.<стихия>`) — в долях, `0.20` = −20 % RES:

```python
# Изумрудная тень 4ч — постоянно
Buff("res_reduction.cryo", 0.40, target=TEAM)

# C2 Мидзуки — только пока она в состоянии «Дрейф грёз»
Buff("res_reduction.cryo", 0.20, target=TEAM, requires=(DREAM,))
```

Множитель считается по кусочной формуле: `1 − RES` при `RES ≥ 0`,
`1 − RES/2` при `RES < 0`, `1/(4·RES+1)` при `RES ≥ 75 %`. Отсюда, например,
`+10 % → 0.90`, а `−10 % → 1.05`.

Дальше движок берёт снижение из статов **атакующего в его текущем состоянии**,
так что удар внутри окна и удар вне его автоматически получают разные
множители — писать это вручную не нужно.

Три способа задать сопротивление, по убыванию приоритета:

| способ | когда | снижения |
|---|---|---|
| `DamageSource(res_override=…)` / `ReactionEvent(res_override=…)` | нужен жёсткий множитель для одного источника | игнорируются |
| `Enemy(res={...})` | обычный случай | вычитаются автоматически |
| `Enemy(res_mult={...})` | готовые множители (как в таблице) | **не** применяются — считается, что уже учтены |

### Свои временные окна

Просто придумайте новый тег — движок ничего о нём не знает:

```python
VV = "viridescent"     # окно шреда от Изумрудной тени
temp(S.DMG_BONUS, 0.15, VV, target=TEAM)
...
occ(4, ON, VV)         # 4 удара внутри этого окна
occ(2, ON, VV, INST)   # 2 удара, когда работают оба окна сразу
```

## 5. Формулы

**Элементальный урон** ([KQM](https://library.keqingmains.com/combat-mechanics/damage/damage-formula)):

```
Урон = (Стат × Множитель + Доп.база) × (1 + Бонус урона) × Защита × Сопр. × Крит × Возвышение
```

**Прямой урон звёздного рассеивания** (из талантов; защита цели НЕ учитывается):

```
База = Стат × Множитель × (1 + Бонус базового урона)
              × (1 + 6·МС/(МС+2000) + Бонус урона звёздной реакции)
Итог = (База + Доп. базовый урон) × Сопр. × Крит × Возвышение
```

**Урон реакции звёздного рассеивания**:

```
Урон = 1446.85 × Базовый множитель × (1 + Бонус базового урона)
              × (1 + 6·МС/(МС+2000) + Бонус урона звёздной реакции)
              × Сопр. × Крит × Возвышение
```

Базовый множитель: `0.75` для анемо-рассеивания; `2` при 1–2 стаках вихря и
`3` при 3–6 стаках для крио-детонации.

Урон реакции считается **для каждого персонажа отряда** и распределяется:

```
Итог = 3/5 · главный + 3/10 · второй + 1/20 · третий + 1/20 · четвёртый
```

Главный — триггер реакции (для анемо) либо сильнейший из крио-персонажей
(для детонации вихря); остальные сортируются по убыванию собственного урона.

> В таблице весь урон реакции записан в столбец триггера. Здесь он
> распределяется по персонажам — сумма та же, разбивка честнее.

## 6. Режим `excel_compat`

```python
Team(..., config=Config(excel_compat=True))
```

`True` — воспроизводит исходную таблицу 1-в-1 (включая её ошибки).
`False` (по умолчанию) — считает строго по формулам выше.

Разница описана в [РАСХОЖДЕНИЯ.md](РАСХОЖДЕНИЯ.md). Коротко: в таблице
множитель `(1 + Base stellar swirl DMG%)` применён к урону реакции **дважды**
(в строке «EMM» и ещё раз в строке урона), из-за чего урон реакций завышен
примерно на 21 %.

## 7. Шпаргалка по статам

| Ключ | Смысл |
|---|---|
| `base_atk` / `atk_pct` / `flat_atk` | итог = `база × (1 + %) + плоская` |
| `base_hp` / `hp_pct` / `flat_hp` | то же для здоровья |
| `base_def` / `def_pct` / `flat_def` | то же для защиты |
| `base_em` / `em_pct` / `flat_em` | `flat_em` прибавляется **после** процентов |
| `crit_rate`, `crit_dmg` | для `crit_mode="expected"` |
| `crit_value` | для `crit_mode="balance"` |
| `dmg_bonus` | общий бонус урона |
| `dmg_bonus.<стихия или тип>` | `dmg_bonus.cryo`, `dmg_bonus.burst`, … |
| `ssw_bonus` | «Stellar Swirl DMG Bonus %» |
| `ssw_base_inc` | «Base DMG Increase %» звёздного рассеивания |
| `elevation` | «Возвышение», итоговый множитель = `1 + elevation` |
| `flat_base_dmg` | «Дополнительный базовый урон» |

Цель (`Enemy`) задаётся **готовыми множителями**, как в таблице:
`res_mult={"anemo": 0.9, "cryo": 1.15}`, `def_mult=0.4875`. Если удобнее
считать из процентов — есть `formulas.resistance_multiplier()` и
`formulas.defense_multiplier()`.
